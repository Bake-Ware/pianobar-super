pianobar
========

pianobar is a free/open-source, console-based client for the personalized
online radio Pandora_.

.. _Pandora: http://www.pandora.com

.. image:: https://6xq.net/pianobar/pianobar-screenshot.png
    :target: https://6xq.net/pianobar/pianobar-screenshot.png
    :alt: pianobar screenshot

Features
--------

- play and manage (create, add more music, delete, rename, ...) stations
- rate songs and explain why they have been selected
- upcoming songs/song history
- customize keybindings and text output (see `configuration example`_)
- remote control and eventcmd interface (send tracks to last.fm_, for example)
- proxy support for listeners outside the USA

.. _last.fm: https://www.last.fm
.. _configuration example: https://codeberg.org/purplesym/pianobar/src/branch/master/contrib/config-example

Install
-------

You need the following software to build pianobar:

- GNU make
- pthreads
- libao
- libcurl ≥ 7.32.0
- gcrypt [1]_
- json-c
- ffmpeg ≤ 5.1 [2]_
- UTF-8 console/locale

.. [1] with blowfish cipher enabled
.. [2] required: demuxer mov, decoder aac, protocol http and filters volume,
        aformat, aresample

Then type::

	gmake clean && gmake

You can run the client directly from the source directory now::

	./pianobar

For a per-user installation (no sudo)::

    make install-user
    pianobar

This installs the executable and web host in ``~/.local/bin`` and the web assets
and manual under ``~/.local/share``. No shell alias is needed. If your shell does
not already search ``~/.local/bin``, add this line to its startup file and open a
new terminal::

    export PATH="$HOME/.local/bin:$PATH"

Use ``make uninstall-user`` to remove the installed app; your configuration and
saved music are retained. Repeat ``make install-user`` after updating this checkout.
For a system installation to ``/usr/local`` use ``sudo make install``. Packaged
upstream versions may not include the web interface or offline features in this fork.

Offline listening and browser interface
---------------------------------------

This checkout automatically saves each song in the background as it loads. Run it from the repository::

    make
    ./pianobar

The web server starts by default. Press ``W`` in the terminal to open it in your
default browser, or open ``http://localhost:8765/`` directly. No link token is
required. Use ``./pianobar --cli`` to disable the web server; the old ``--web`` option has been replaced by ``--cli``.
The browser and terminal control
one player: playback, ratings, station creation and management, discovery,
bookmarks, history, settings, and the remaining commands are available as buttons.
Actions that need more information open an interactive dialog with the player's
choices and an answer field. Custom keybindings and disabled commands are
respected. The web page accepts the same configured, case-sensitive hotkeys,
including Space; the collapsible legend below the player starts closed and shows
the keys and which actions are available. Hotkeys pause in text fields and dialogs, and leave Ctrl/Alt/Meta
browser shortcuts alone. Held keys do not repeat commands.

The **Settings** page handles first-run setup. Add your Pandora email/password
and choose **Save & start listening**, or enable offline startup to use an
existing library without an account. Authentication still uses the native Pandora
client; login/network errors do not close the web interface, so you can correct
settings and retry.

Settings includes automatic saving, the library folder, offline startup/fallback,
audio quality/buffering, default audio output, and web listen address/port/password.
**Save settings** stores changes for the next start. **Save & restart player**
applies account and listening settings immediately, interrupting playback; wait
for pending song saves before restarting. Web address and password changes take
effect when you restart the whole ``pianobar`` app. Explicit command-line options
override saved defaults.

Native settings remain in ``~/.config/pianobar/config`` (or
``$XDG_CONFIG_HOME/pianobar/config``), preserving custom keys and comments.
Web defaults are stored beside it in ``web.json``. Passwords are stored as plain
text in owner-only files (mode 0600), never returned by the settings API or placed
in browser storage. Leave password fields blank to keep existing credentials.
An existing ``password_command`` remains usable unless you replace or forget the
Pandora password. Pandora credentials and the web access password are separate.

Choose **Host**, **Browser**, or **Both** in the player to route audio. Selecting
Browser or Both starts playback in that tab; **Listen here** lets another tab or
device join, and **Stop listening** disconnects just that browser. The shared
player still controls the track, volume, and pause state. Browser playback has a
small buffering delay, so Both is not synchronized across devices. To start on a
computer without speakers, use ``./pianobar --output browser``. Browser audio
uses Web Audio and requires a click or other user interaction to start.
New pages request **Listen here** automatically by default. Disable this in
**Settings → This browser** to use that browser as a remote control only.
The preference saves immediately in localStorage and applies on the next page
load. If the browser blocks autoplay, click **Listen here** to allow sound.
Auto-listen preserves host speakers by switching Host to Both when necessary;
it joins once and respects later manual stops and remote routing changes.
The browser starts with a 900ms buffer and increases it up to 2.5 seconds if the
connection underruns. This adds latency but tolerates uneven delivery. Audio is
losslessly gzip-compressed when supported; it is still PCM, so budget up to
1.4 Mbps per listener for 44.1 kHz stereo before compression. Status responses
are compressed too. Album art is privately cached by the browser for one hour,
and failed player artwork requests retry up to three times.

On phones, artwork and controls stack vertically, with persistent bottom
navigation and touch-sized buttons. **Station tools** expands the station
management groups; the keyboard legend remains collapsed by default.

The header's dark-mode toggle remembers your choice in localStorage (and uses
your system theme until you choose one). Stations and Library navigation open
dedicated station controls and saved-library pages; reload and browser Back
preserve navigation. Find your next favorite and Make it yours are collapsible
sidebar groups. The browser tab title follows the current station and track.
Player activity follows the latest output as a faint background inside the player
controls, clipped to the panel. It is hidden on Stations and Library. Library shows
only saved songs, with Make it yours hidden. Controls sit on the left and album art on the right. On narrow screens,
the artwork moves below the controls.

The Stations page lists all stations loaded from your Pandora account, including
the shuffle mix. Search by name and click **Play** to switch stations. Station
selection is unavailable offline; reconnect to load the list after an offline
startup. The current station is marked, and station-management actions remain
available below the list and in the sidebar. Deleting a station opens a
confirmation naming the station; Cancel is focused by default, and Escape cancels.

The Library view lists completed saved songs with title, artist, album, and
length, plus cached artwork thumbnails. Artwork downloads in the background,
independently of audio, and is shared by matching artist/album metadata. Cached
images are stored in ``cache_dir/artwork`` and work offline in Library, the
player, the sidebar thumbnail, and the favicon. Tracks without artwork use a
placeholder. Older saved tracks pick up artwork when the matching album plays
again; their original files do not contain cover URLs for automatic backfilling.
Search by any of those text fields, then use a song's **Play** button to
switch immediately to local playback. The selected song plays first; when it
ends, playback continues through the shuffled saved library. Use **Reconnect**
to return online. The list refreshes while Library is open, and the **Refresh**
button picks up new or removed files immediately. Library metadata scans run in
a separate process so browsing does not interrupt audio.

The web host requires Python 3.9 or newer and uses only its standard library.
Its scripts, styles, and artwork placeholder are served locally, including when
offline. It binds to localhost; additional tabs can open the same address directly.
Host and origin checks reject requests from other websites. Choose another port with
``./pianobar --port 8888``. ``make install`` installs the host and assets
alongside the native player.

To host the interface on your local network::

    ./pianobar --listen 0.0.0.0

Open ``http://<this-computer's-LAN-address>:8765/`` from another device. Network
mode uses HTTP Basic authentication with username ``pianobar`` and a generated
password printed in the terminal. To reuse a password, put it in a private file
and pass ``--password-file /path/to/password``. The file is read at startup;
without it, the generated password changes on each launch. IPv6 addresses are
also accepted, for example ``--listen ::``. Network and output options cannot
be combined with ``--cli``. The built-in server serves HTTP on the specified
interface; it does not terminate TLS.

To start without a Pandora login or internet connection::

    ./pianobar --offline
    ./pianobar --cli --offline

Press ``O`` or use the browser's **Go offline / Reconnect** button to change
modes. Offline mode shuffles all completed songs and repeats the library. Play,
pause, skip, volume, song information, and upcoming tracks remain available.
Pandora account/station changes are disabled offline. Reconnect explicitly when
you want to return online; a failed reconnect keeps local playback available.
An empty library produces a message and exits when starting with ``--offline``.

Defaults, configurable in ``~/.config/pianobar/config``::

    cache_songs = 1
    cache_dir = ~/.local/share/pianobar/songs
    offline = 0
    offline_fallback = 1
    act_offline = O
    act_web = W

If ``XDG_DATA_HOME`` is set to an absolute path, the default music directory is
``$XDG_DATA_HOME/pianobar/songs``. ``cache_dir`` supports ``~/`` expansion. Saved
songs use standard Matroska audio (``.mka``) files with title, artist, album, and
gain metadata. Each loaded online song starts an independent background download,
without waiting for playback to finish. Pause, skip, or change stations and the
save continues. This uses a separate request from streaming playback, so it can
use more bandwidth. Audio packets are saved without re-encoding. Filenames are
hashes of song metadata and encoding; the same song/quality is deduplicated both
in the download queue and against existing completed copies.

To prepare for a trip, load songs and skip ahead, then leave pianobar running and
connected until the footer's **Saving … songs for offline** message clears.
Library refreshes automatically and lists only completed saves. Two downloads run
at once, with up to 64 active/waiting songs; a full queue reports a message.
Each song must be loaded into the player to enter the save queue.

Only clean, complete downloads are published. Failed downloads are discarded;
loading the song again retries the save. Quitting cancels unfinished downloads,
so wait for them to finish before exiting or disconnecting. A force-killed process can leave hidden
``.partial-*`` files; these are never played and may be removed while the player
is stopped. Cache write failures leave streaming playback running. There is no
storage cap or automatic eviction: remove saved files yourself to free space,
or set ``cache_songs = 0`` to stop saving new songs while retaining offline play.
The FFmpeg build must include the Matroska muxer and demuxer for this feature.

With ``offline_fallback = 1``, network failures during login (with credentials
configured), playlist retrieval, or streaming switch to saved music if available.
API connection errors use one attempt before fallback, bounded by ``timeout``
(default 30 seconds). Authentication errors remain visible rather than silently
switching modes. Set ``offline_fallback = 0`` to use the existing API retry policy.

Audio output buffering
~~~~~~~~~~~~~~~~~~~~~~

``audio_buffer_ms = 200`` sets a 200ms output buffer for libao's ALSA, PulseAudio,
and OSS drivers, giving audio delivery more tolerance for scheduling delays.
This is separate from ``buffer_seconds``, which controls the decoded stream
buffer. The tradeoff is a small increase in pause/volume response latency.
Set ``audio_buffer_ms = 0`` to use the driver's own defaults; accepted values
are 0–2000. Other drivers retain their own buffering. Volume changes are
serialized with the audio filter graph, and output-device errors are reported
instead of silently dropping audio. Restart pianobar for buffering changes.

Development checks::

    make test
    # Optional browser interaction and layout tests, with Playwright installed:
    python3 tests/web.py --browser
    python3 tests/network.py --browser

Tests generate AAC/MP3 fixtures, serve them over a local HTTP server, and send
sound to a FIFO. They need Python 3, ffmpeg, and ffprobe, but no Pandora account or
audio hardware. Live Pandora login and account mutations require separate testing
with an account.

FAQ
---

The audio output does not work as expected. What can I do?
    pianobar uses libao and most problems are related to a broken libao
    configuration. Have a look at issue `#167`_ for example.
Can I donate money? Do you have a Flattr/Bitcoin/… account?
    No, money is not necessary to continue working on pianobar. There are many
    other ways to support pianobar: Reporting bugs, creating `cool stuff`_
    based on pianobar, blogging about it and the most important one: Keeping
    Pandora alive.

REST API and Rook control
-------------------------

All player controls and per-browser audio routing are available through the
REST API and Rook capabilities. Open pages register automatically; name each
page beside **Listen here** and route audio to one, several, all, or none.
See ``integrations/README.md`` for endpoints, authentication, browser activation,
and the Rook capability manifest.

Android app and device downloads
--------------------------------

The generic Android companion starts without a server address. Configure your
server in its Settings screen, then open the existing web player. It uses the
installed browser's sign-in session and supports all server web controls.
See `Android setup and builds <android/README.md>`_ for APK build instructions,
the GitHub Actions template, signing, and device tests.

The web Library includes a **Download** link for each saved track. Downloads
require the same authentication as playback. Cached AAC is exported as M4A and
MP3 as MP3, without re-encoding, with metadata and available JPEG/PNG artwork.
Install the ``ffmpeg`` and ``ffprobe`` command-line tools on the server to enable
exports. Two exports can be prepared at once; downloads leave the saved library
and active playback unchanged.

In the Android app, use **Downloads → Add downloaded tracks** to import those
files into its on-device library for background playback without the server.
